HTTP의 특징 중의 하나는 **무상태 프로토콜**을 지향한다는 것이다.

### 무상태 프로토콜이란?
Stateless로, 서버가 클라이언트의 이전 요청이나 상태를 기억하지 않는 구조이다.

**장점**
- 서버를 쉽게 늘리고 줄일 수 있다.(스케일 아웃에 유리)
- 특정 서버에 문제가 생겨도 다른 서버가 요청을 대신 처리할 수 있다.

**단점**
- 매 요청마다 필요한 정보를 모두 포함해야 하므로 데이터 양이 늘어날 수 있다.

### 상태 유지 프로토콜이란?
Statefyul로, Stateless의 반대이고 서버가 클라이언트의 이전 요청이나 상태를 계속 기억하고 있는 구조이다.

### Stateless 예시
- 고객: 이 **노트북** 얼마인가요?
- 점원A: 100만원 입니다.

<br>

- 고객: **노트북 2개** 하겠습니다.
- 점원B: 노트북 2개는 200만원 입니다. **신용카드**, **현금** 중에 어떤 걸로 구매하시겠어요?

<br>

- 고객: **노트북 2개를 신용카드**로 구매하겠습니다.
- 점원C: 200만원 결제 완료되었습니다.

Stateful은 도중에 서버가 망가지면 client는 처음부터 해야하지만 Stateless는 중간에 서버가 장애가 나도 request를 한꺼번에 보내기 때문에 상관없이 response를 받을 수 있다.

## Stateless의 한계
- 모든 것을 무상태로 설계할 수 있는 경우도 있고 없는 경우도 있다.
- 무상태
  - ex. 로그인이 필요 없는 단순한 서비스 소개 화면
- 상태 유지
  - 로그인
- 로그인한 사용자의 경우 로그인 했다는 상태를 서버에 유지
- 일반적으로 브라우저 쿠키와 서버 세션 등을 사용해서 상태 유지
- 상태 유지는 최소한만 사용
