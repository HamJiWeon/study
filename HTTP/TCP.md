## TCP, UDP란?

- **TCP**:  
  - Transmission Control Protocol로 애플리케이션 사이에서 안전하게 데이터를 통신하는 규약  
  - IP의 단점들을 보완  

- **UDP**:
  - User Datagram Protocol로 연결 설정이나 확인 응답 없이 데이터를 빠르게 일방적으로 전송하는 비연결형 전송 규약

## TCP 통신 과정
네트워크에서 데이터를 통째로 통신하는 경우는 거의 없다. 예를 들어 이미지를 전송할 때 여러 조각으로 나누어 각 조각을 따로 전달한 뒤 합칠 수 있다.
1. 데이터 스트림에서 받은 데이터를 일정 단위로 분할
2. 분할된 데이터 단위에 TCP 헤더를 붙여서 TCP 세그먼트를 생성
3. TCP 세그먼트를 IP 데이터크램으로 변환
   - **[IP 데이터 그램](https://github.com/HamJiWeon/study/blob/main/HTTP/1.%20IP.md)**: 인터넷 통신에 사용되는 데이터 패킷
4. IP 데이터그램을 수신 애플리케이션에 보냄

### TCP 세그먼트
TCP 세그먼트는 헤더와 데이터 필드가 나뉘어져 있다.
- **Source Port**: 데이터를 발송하는 애플리케이션의 포트 번호
- **Destination Port**: 데이터를 수신하는 애플리케이션의 포트 번호
- **Sequence Number(SYN)**: TCP 통신 과정에서 데이터를 일정 단위로 분할된 데이터의 순서
- **Acknowledgement Number(ACK)**: 데이터를 수신하는 애플리케이션 입장에서 다음으로 받고 싶은 TCP 세그먼트의 Sequence Number

## TCP 특징
- **연결형 서비스**: 통신 전 3-way handshake로 연결을 맺고, 통신 후 4-way handshake로 연결을 끊음
- **신뢰성 보장**: 패킷 손실 시 재전송을 요청해 데이터 유실을 막음
- **순서 보장**: 수신된 데이터의 순서가 바뀌지 않도록 번호를 부여해 재조립
- **양방향 통신**: 전이중(Full-Duplex) 방식으로 양쪽에서 동시에 송수신이 가능

### TCP 3 way handshake
TCP 통신을 하려면 데이터를 발송하는 애플리케이션, 수신하는 애플리케이션 모두 준비가 됐다는 것을 보장하기 위해 네트워크 연결 설정이 먼저 필요함.(데이터를 정확하게 전달하기 위해 세션을 만드는 중요한 과정)

1. **SYN**:
    - 클라이언트가 서버에게 SYN(synchronize) 플래그가 설정된 메시지를 보낸다. 이때 SYN은 클라이언트의 임의 시퀀스 번호 A를 포함한다.
2. **SYN-ACK**:
    - 서버는 클라이언트의 SYN에 응답하여 SYN-ACK 메시지를 보낸다. 서버는 자신만의 새로운 시퀀스 번호 B를 포함한 SYN을 전송하고, 클라이언트의 시퀀스 번호 A에 +1을 한 ACK를 함께 보낸다.(A+1)
3. **ACK**:
    - 클라이언트는 서버로부터 받은 SYN에 대해 ACK 메시지를 전송한다. 이때 ACK는 서버의 시퀀스 번호 B에 1을 더한 값(B+1)을 포함한다.
