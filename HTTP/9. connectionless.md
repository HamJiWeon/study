## 비연결성이란?
connectionless란 클라이언트와 서버가 한 번 연결을 맺은 후, 클라이언트 요청에 대해 서버가 응답을 마치면 연결을 끊어버리는 성질을 말한다.

## 비연결성
### 특징
- HTTP는 기본이 연결을 유지하지 않는 모델
- 일반적으로 초 단위 이하의 빠른 속도로 응답
- 1시간 동안 수천명이 서비스를 사용해도 실제 서버에서 동시에 처리하는 요청은 수십개 이하로 매우 작음
  - ex. 웹 브라우저에서 계속 연결해서 검색 버튼을 누르지는 않음
- 서버 자원을 매우 효율적으로 사용할 수 있음

### 비연결성의 한계와 극복
- TCP/IP 연결을 새로 맺어야 함 - 3 way handshake 시간 추가
- 웹 브라우저로 사이트로 요청하면 HTML 뿐만 아니라 JS, CSS, 추가 이미지 증 수 많은 자원이 함께 다운로드
- 지금은 HTTP 지속 연결(Persistent Connections)로 문제 해결
- HTTP/2, HTTP/3에서 더 많은 최적화

**지속 연결**

매번 새로운 TCP 연결을 맺지 않고, 하나의 TCP 연결을 재사용해 여러 개의 HTTP 요청과 응답을 주고받는 통신 방

```text
┌──────────┐                    ┌──────────┐
|          |  conn        0.1s  |          |
|          |────────────────────|          |
|          |  req         0.1s  |          |
|          |────────────────────|          |
|  Client  |  req         0.1s  |  Server  |
|          |────────────────────|          |
|          |  req         0.1s  |          |
|          |────────────────────|          |
|          |  end         0.1s  |          |
└──────────┘                    └──────────┘
합: 0.5초
```

**장점**:
- 속도 향상: TCP 3-way handshake 과정을 생략하므로 지연 시간(Latency)이 줄어듭니다.
- 자원 절약: TCP 연결을 맺고 끊는(Handshake/Teardown) 네트워크 트래픽과 서버 부하가 감소합니다.

**단점**:
- 자원 낭비(유휴 상태): 클라이언트가 요청을 보내지 않고 대기하는 동안에도 서버는 연결을 유지해야 하므로 메모리와 CPU 자원이 소모됩니다.
- 과부하 위험: 접속자가 많은 서버에서 유휴 연결이 지나치게 쌓이면 서비스 거부(DoS)와 유사한 자원 고갈 상태가 발생할 수 있습니다.
