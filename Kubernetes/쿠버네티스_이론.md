## 쿠버네티스란?
다수의 컨테이너를 효율적으로 배포, 확장 및 관리하기 위한 오픈소스 시스템이다.  
쿠버네티스는 Doker Compose와 비슷한 느낌을 가지고 있다. compose도 다수의 컨테이너를 쉽게 관리하기 위해 활용하기 때문이다. 쿠버네티스의 대략적인 이미지를 그릴 때는 Docker Compose의 확장판이라고 생각하면 편하다.

### 쿠버네티스의 장점
- 컨테이너 관리 자동화(배포, 확장, 업데이트)
- 부하 분산(로드 밸런싱)
- 쉬운 스케일링
- 셀프 힐링

## 개념
### Pod란?
도커에서는 하나의 프로그램을 실행시키는 단위를 **컨테이너**라고 불렀는데, 쿠버네티스에서는 Pod라고 부른다. 따라서 pod는 일반적으로 쿠버네티스에서 하나의 프로그램을 실행시키는 단위라고 생각하면 편하다.
>- 쿠버네티스에서 가장 작은 단위
>- 일반적으로 하나의 pod가 하나의 container를 가진다.
>    - 예외적으로 하나의 pod가 여러 개의 container를 가지는 경우도 있다.

### NginX Pod 만들어보기
```yaml
# nginx-pod.yaml

apiVersion: v1
kind: Pod

metadata:
  name: nginx-pod

spec:
  containers:
    - name: nginx-container
      image: nginx
      ports:
        - containerPort: 80
```

nginx-pod.yaml 파일을 작성해준다.

```bash
kubectl apply -f nginx-pod.yaml
```

을 하게되면 pod가 만들어지는데 확인을 해보려면 `kubectl get pods`을 쳐보면 된다.
```bash
NAME        READY   STATUS    RESTARTS   AGE
nginx-pod   1/1     Running   0          44s
```
그럼 결과는 위의 결과와 같이 잘 나오는 것을 알 수 있다. 하지만 localhost:80을 들어가보면 연결이 안 된다.  
그 이유로는 [도커](https://github.com/HamJiWeon/study/blob/main/Docker/%EB%8F%84%EC%BB%A4_%EC%A0%84%EC%B2%B4_%ED%9D%90%EB%A6%84_%EC%95%8C%EC%95%84%EB%B3%B4%EA%B8%B0.md) 때와 같이 컨테이너 내부와 컨테이너 외부의 네트워크가 서로 독립적으로 분리되어 있었다.
하지만 쿠버네티스에서는 pod 내부의 네트워크를 컨테이너가 공유해서 같이 사용한다. pod의 네트워크는 로컬 컴퓨터의 네트워크와는 독립적으로 분리되어 있다. 이 때문에 pod로 띄운 NginX에 아무리 요청을 보내도 응답이 없었던 것이다.

NginX가 띄우는 웹 페이지에 접근하려면 2가지 방법이 있다.
- 1. Pod 내부로 들어가서 접근하기
- 2. Pod의 내부 네트워크를 외부에서도 접속할 수 있도록 포트 포워딩을 활용하기
